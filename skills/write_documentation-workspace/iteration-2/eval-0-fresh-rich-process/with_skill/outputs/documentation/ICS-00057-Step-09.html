Идентификатор ICS-00057-Step-09
Определение UploadEvidenceStep
Пользователь Bot
Входные данные
  • ReportingPeriod из Step-01
  • sapScreenshotsStorageName, sapUnloadingStorageName из Step-02
  • checklistAccounts, mtComments из Step-08
  • InitParameters: storageFolderName, spVactpro*, unloadingFileName, screenshotsFileName, emailRecipients
Основной путь
  1. Бот создаёт временную папку и скачивает из Хранилища скриншоты и выгрузку (в подкаталоги screenshots/ и input data/);
  2. Бот формирует чек-лист ICS-00057_01.xlsx (ExcelChecklistHelper, сортировка по номеру счета);
  3. Бот упаковывает скриншоты, выгрузку и чек-лист в ZIP-архив технической проверки и считает MD5-контрольную сумму;
  4. Бот загружает чек-лист и архив в Orchestrator Storage (плоское имя с суффиксом даты-времени);
  5. Бот загружает файлы в SharePoint по унифицированной структуре папок периода (выгрузка → input data, скриншоты → screenshots, чек-лист и архив → корень рабочей папки);
  6. Бот обновляет файлы состояния ics00057_accounts.json и ics00057_comments.json в Хранилище (ProcessStateService);
  7. Бот удаляет временный каталог и отправляет письмо work_end со ссылкой на папку SharePoint.
Альтернативные пути —
Выходные данные
  • чек-лист ICS-00057_01.xlsx и технический ZIP-архив в SharePoint и Хранилище;
  • обновлённые ics00057_accounts.json и ics00057_comments.json;
  • md5Checksum в транзакции;
  • письмо work_end со ссылкой на результаты.
Дополнительные требования Бот-сессия разрывается на MT-шагах, поэтому локальные файлы из Step-02 не переживают запуск — выгрузка и скриншоты скачиваются из Хранилища заново.
