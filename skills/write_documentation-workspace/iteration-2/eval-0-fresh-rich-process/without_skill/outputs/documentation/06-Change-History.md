## Ключевые архитектурные сдвиги

1. **S3 → Orchestrator Storage** (`88c2cdf`) — отказ от S3 в пользу Storage оркестратора.
2. **DataStore → Orchestrator Assets** (`3214dff`) — состояние справочника/комментариев в Storage-файлах `ics00057_accounts.json` / `ics00057_comments.json`.
3. **Плоские имена с датой** (`5b11346`, `ce12917`) — компенсация отсутствия структуры папок в Storage суффиксом `yyyyMMdd_HHmmss`.
4. **Стадии Stage1–Stage4** (`4215043`) — разделение на 4 стадии с разрывом бот-сессии на MT-шагах; каждая стадия стартует из Task Queue-триггера.
5. **Auto-trigger** (`ab55150`, `abb4748`) — программное создание MT-задачи в финальном состоянии для пропуска ручной проверки при отсутствии данных.
6. **Финализация задачи в любой ветке** (`fec01e4`, `cdddb84`, `32e1628`) — обязательный `SUCCESS` + `processed*` для защиты от повторного auto-trigger.
7. **Унифицированная структура папок SharePoint** (`bebf8f0`, `47e0495`, `0c5190f`, `ab6d99b`) — единый источник истины `FolderStructure`, используется `SapStep` и `UploadEvidenceStep`.
8. **Выравнивание email-подписей с ODF** (`88c1c5d`) — приведение шаблонов `process_started` / `process_error` к единому корпоративному стилю.
