Идентификатор ICS-00012-Step-03
Определение JiraTicketCreation
Пользователь Bot
Входные данные
  • init параметры (jiraUrl, issueProject, issueType, issueComponent, issueAssignee, issueSummary, issueDescription, fileDirectory, countLimit)
  • scriptResult (Integer) из Step-02
  • dateTime (String) из Step-02
Основной путь
  1. Бот получает учётные данные jira_jsd_credentials из Orchestrator;
  2. Бот создаёт клиент Jira (JiraJsdUtils) с login/password и jiraUrl;
  3. Бот формирует описание тикета, подставляя count, directory, count_limit в шаблон issueDescription;
  4. Бот формирует структуру Issue (project, issueType, summary, description, component, customField_18311);
  5. Бот создаёт задачу в Jira и получает issueId;
  6. Бот назначает исполнителя задачи issueAssignee через assignIssue;
  7. Бот сохраняет ticketId в транзакцию.
Альтернативные пути Если возвращённый issueId пуст или null, Бот выбрасывает IllegalStateException.
Выходные данные
  • ticketId (String) — ключ созданной задачи Jira (например, SOX-12345)
Дополнительные требования Шаг выполняется только при isTicketNeeded=true
Возможные исключения ICS-00012-EX-03
