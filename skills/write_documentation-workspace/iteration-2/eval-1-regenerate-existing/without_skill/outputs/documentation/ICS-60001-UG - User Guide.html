Краткое описание процесса

Процесс автоматически получает данные из SAP, формирует случайную выборку ручных проводок, обогащает их владельцами из MIM, рассылает задания на проверку и формирует итоговый отчёт с техническим архивом в SharePoint. В работе процесса задействованы два web-действия Orchestrator: document-type-policy-editor (редактор справочника типов документов) и document-review (проверка документа).

ICS-60001-Step-04 Редактирование списков типов документов (web-интерфейс)
  • Открывает web-интерфейс document-type-policy-editor

  • Сохраняет изменения (тег задачи меняется на policyUpdated)
  • Предоставляет ссылку на редактор и начальные данные
ICS-60001-Step-05 Сохранение утверждённых списков в ресурсы Orchestrator Нет
  • Читает задачу с тегом policyUpdated
  • Обновляет ресурсы document_type_classification и document_type_comments
  • Отправляет task_completed «Обновление справочника»
ICS-60001-Step-06 Подготовка случайной выборки Нет
  • Группирует позиции по документам, фильтрует по allowed-типам
  • Считает размер выборки (2/5/15/25), перемешивает, сортирует
ICS-60001-Step-07 Обогащение выборки владельцами и контролёром через MIM Нет
  • Выполняет PowerShell-запросы к MIM (accounts, persons)
  • Формирует OwnerContact (email, fullName, active)
  • Определяет контролёра по controllerEmail
ICS-60001-Step-08 Рассылка заданий исполнителям и контролёру
  • Получает письмо «multitask_new» (активные владельцы) с таблицей документов
  • Контролёр получает task_assigned «Проверка ручных проводок»
  • Фильтрует активных владельцев, формирует mainTable
  • Отправляет письма через шаблон multitask_new и task_assigned
  • Создаёт задачи documentReview в очереди «ICS-60001 Document review»
ICS-60001-Step-09 Обработка документа (web-интерфейс)
  • Открывает web-интерфейс document-review
  • Просматривает информацию о документе и позициях
  • Загружает подтверждающий файл, выбирает статус («OK»/«NOT OK»), вводит комментарий
  • Сохраняет результат
  • Предоставляет интерфейс проверки и начальные данные
ICS-60001-Step-10 Финализация и публикация результатов
  • Получает уведомление process_completed со ссылкой на результаты в SharePoint
  • Собирает результаты проверки из очереди «ICS-60001 Document review»
  • Заполняет шаблон ICS-60001.xlsx, загружает доказательства
  • Собирает ZIP-технический архив, загружает в SharePoint
  • Отправляет task_completed и process_completed

Работа Исполнителя с web-интерфейсами

Редактор списков типов документов (document-type-policy-editor)

Открывается по ссылке из параметра documentTypePolicyEditorActionLink. В таблице представлены вид документа, комментарий и признак «Включены». Исполнитель:

  1. редактирует комментарии к типам документов;
  2. включает/отключает типы документов (allowed/denied) для проверки;
  3. нажимает «Сохранить» — форма отправляет обновлённый initialData в задачу и меняет тег на policyUpdated.

Важно: форма должна отправлять валидный JSON-объект. Если в Orchestrator попадёт строка [object Object], шаг 5 завершится с BusinessException.

Проверка документа (document-review)

Открывается по ссылке из параметра documentReviewActionLink. На экране две таблицы: «Информация о документе» (атрибуты группы) и «Позиции документа» (позиции проводки). Исполнитель:

  1. выбирает подтверждающий файл (обязательно) и загружает его;
  2. выбирает статус «OK» или «NOT OK»;
  3. вводит комментарий (опционально);
  4. нажимает «Сохранить» — форма отправляет userInput = {uploadedFileGuid, uploadedFileName, status, comment} в задачу.

До завершения процесса задание можно повторно открыть и скорректировать.
