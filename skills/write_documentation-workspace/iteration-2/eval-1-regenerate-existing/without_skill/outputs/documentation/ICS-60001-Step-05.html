Идентификатор ICS-60001-Step-05
Определение Сохранение утверждённых списков типов документов в ресурсы Orchestrator
Класс Java by.a1.ics60001.steps.PersistDocumentTypeListsStep
Пользователь Bot
Входные данные
  • Очередь задач Orchestrator «ICS-60001 Document type policy editor» (ищется задача с тегом policyUpdated)
  • Параметр задачи initialData = {allowedDocList, deniedDocList}
  • InitParameters: emailRecipients
Основной путь
  1. Бот получает список задач из очереди «ICS-60001 Document type policy editor» и выбирает первую с тегом policyUpdated;
  2. Бот разбирает initialData (Map или JSON-строка) в allowedDocList и deniedDocList;
  3. Бот собирает уникальные коды allowed/denied (TreeSet) и общую map комментариев;
  4. Бот формирует dictionaryList (List<DocumentTypeEntry> с полями code, allowed, comment) и сохраняет в транзакцию dictionary.list;
  5. Бот обновляет ресурсы Orchestrator: document_type_classification (JSON с allowedDocTypes/deniedDocTypes, тип TEXT) и document_type_comments (JSON Map<String,String>, тип TEXT);
  6. Бот отправляет sendTaskCompleted с контекстом mtName=«Обновление справочника».
Альтернативные пути Если initialData пришёл как [object Object] — бот выбрасывает BusinessException с явной диагностикой. При любом исключении бот выбрасывает BusinessException («Persist document type lists failed»).
Выходные данные
  • Transaction: dictionary.list (List<DocumentTypeEntry>)
  • Обновлённые ресурсы Orchestrator: document_type_classification, document_type_comments
  • Email task_completed «Обновление справочника»
Дополнительные требования Корректность JSON из web-формы (валидный объект, а не строковое [object Object]).
Возможные исключения ICS-60001-EX-01
