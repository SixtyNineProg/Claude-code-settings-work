Идентификатор ICS-60001-Step-08
Определение Рассылка заданий исполнителям и контролёру, создание задач documentReview
Класс Java by.a1.ics60001.steps.SendMultitaskNotificationStep
Пользователь Bot
Входные данные
  • Transaction: sample.documents, owners.enriched, sample.owners, опционально controller.name
  • Credentials: sherpa_api_credentials
  • InitParameters: emailRecipients, controllerEmail, processName, controlName, documentReviewActionLink
  • Ресурс ics60001_email_templates (шаблон multitask_new)
  • Системное свойство transaction.path
  • Очередь «ICS-60001 Document type policy editor» (берётся первая задача для обновления)
Основной путь
  1. Бот фильтрует активных владельцев (active=TRUE, email заполнен, sapLogin в sampleOwners) → activeOwnerEmails; собирает неактивных логины → inactiveOwnerLogins;
  2. Бот строит mainTable из sampleDocs: number, docNumber, date (postingDate с заменой «/» на «.»), currency=«BYN», userName, text (из первой позиции), amount (позиции bookAmount через «<br>»), account (номера счетов через «<br>»);
  3. Бот формирует контекст письма: processName, controllerEmail, controllerName (или controllerEmail), controlName, expireDate/expireTime (текущее UTC→Europe/Minsk, минуты обнуляются), inactiveEmailUsers (если есть), mainTable;
  4. Бот отправляет sendByTemplateName("multitask_new", context, recipients) активным владельцам (to=activeOwnerEmails, cc=emailRecipients.to);
  5. Бот отправляет sendTaskAssigned с actionUrl=documentReviewActionLink, mtName=«Проверка ручных проводок» контролёру (to=emailRecipients.to, cc=emailRecipients.cc);
  6. Для каждого документа из sample.documents бот создаёт задачу documentReview в очереди «ICS-60001 Document review» с тегом pendingReview и параметрами initialData={sampleDoc, bearerToken=sherpaApiCredentials.password};
  7. Бот обновляет первую задачу в очереди «ICS-60001 Document type policy editor», передавая transactionName и processStage=3.
Альтернативные пути Если activeOwnerEmails пуст — письмо владельцам не отправляется (логируется warning). Если emailRecipients.to пуст — письмо контролёру не отправляется. При любом исключении бот выбрасывает BusinessException («Send multitask notifications failed»).
Выходные данные
  • Email «multitask_new» активным владельцам
  • Email task_assigned «Проверка ручных проводок» контролёру
  • Задачи documentReview (тег pendingReview) в очереди «ICS-60001 Document review» — по числу документов выборки
  • Обновлённая задача в очереди «ICS-60001 Document type policy editor» (processStage=3)
Дополнительные требования Возможность повторной рассылки при ошибке; системное свойство transaction.path обязательно.
Возможные исключения ICS-60001-EX-01
