Идентификатор ICS-60001-Step-03
Определение Подготовка списков типов документов (allowed/denied/unclassified) и постановка задания в очередь редактора справочника
Класс Java by.a1.ics60001.steps.PrepareDocumentTypeListsStep
Пользователь Bot
Входные данные
  • Transaction: accounting.document.positions
  • Ресурс document_type_classification (DocumentTypeClassification: allowedDocTypes/deniedDocTypes)
  • Ресурс document_type_comments (Map<String,String>)
  • InitParameters: documentTypePolicyEditorActionLink, emailRecipients
  • Системное свойство transaction.path (для имени транзакции)
Основной путь
  1. Бот загружает document_type_classification (allowed/denied) и document_type_comments;
  2. Бот проходит по AccountingDocumentPosition и собирает коды видов документов, не входящие ни в allowed, ни в denied → unclassified;
  3. Бот формирует три списка пар {code: comment} (allowed, denied, unclassified), сортирует каждый по коду;
  4. Бот сохраняет в транзакцию doc.types.white.list, doc.types.black.list, doc.types.unclassified.list;
  5. Бот ставит в очередь Orchestrator «ICS-60001 Document type policy editor» задачу documentTypePolicyEditor с тегом pendingPolicyUpdate и параметрами initialData={allowedDocList, deniedDocList}, transactionName, processStage=2;
  6. Бот отправляет sendTaskAssigned с контекстом actionUrl=documentTypePolicyEditorActionLink, mtName=«Обновление справочника».
Альтернативные пути Пустой/отсутствующий document_type_comments — бот использует пустой map и логирует warning. Ошибка постановки задачи в очередь — бот выбрасывает исключение, процесс завершается с ошибкой.
Выходные данные
  • Transaction: doc.types.white.list, doc.types.black.list, doc.types.unclassified.list
  • Задача в очереди «ICS-60001 Document type policy editor» с тегом pendingPolicyUpdate
  • Email task_assigned «Обновление справочника»
Дополнительные требования Системное свойство transaction.path обязательно — без него бот выбрасывает IllegalStateException.
Возможные исключения ICS-60001-EX-01
