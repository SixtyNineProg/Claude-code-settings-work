Идентификатор ICS-60001-Step-08
Определение Рассылка заданий исполнителям
Пользователь Bot
Входные данные
  • sampleDocuments, sampleOwners, ownersEnriched
  • controllerName из транзакции
  • InitParameters.controllerEmail, controlName, processName, documentReviewActionLink, emailRecipients
  • asset sherpa_api_credentials
Основной путь
  1. Бот разделяет sampleOwners на activeOwnerEmails (активные персоны с email) и inactiveOwnerLogins;
  2. Бот строит mainTableRows из sampleDocuments (номер, дата, сумма, счёт, пользователь, текст);
  3. Бот формирует контекст письма (processName, controlName, controllerEmail, controllerName, expireDate, expireTime, inactiveEmailUsers, mainTable) и отправляет шаблон multitask_new активным владельцам (to) и emailRecipients.to (cc);
  4. Бот отправляет контролёру email task_assigned со ссылкой documentReviewActionLink (mtName="Проверка ручных проводок");
  5. Бот создаёт в очереди "ICS-60001 Document review" задачи documentReview (тег pendingReview) для каждого документа из sampleDocuments с параметрами sampleDoc и bearerToken (sherpa_api_credentials.password());
  6. Бот обновляет задачу documentTypePolicyEditor параметрами transactionName и processStage=3.
Альтернативные пути Если активных email-владельцев нет — письмо multitask_new не отправляется. Если emailRecipients.to пуст — письмо контролёру не отправляется.
Выходные данные
  • письма multitask_new владельцам и task_assigned контролёру
  • задачи documentReview в очереди "ICS-60001 Document review"
Дополнительные требования Web-action document-review должен быть опубликован, ссылка на него задана в init-параметрах.
Возможные исключения ICS-60001-EX-07
