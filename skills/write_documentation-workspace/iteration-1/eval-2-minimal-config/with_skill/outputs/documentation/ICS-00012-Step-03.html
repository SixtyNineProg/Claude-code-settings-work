Идентификатор ICS-00012-Step-03
Определение Jira Ticket Creation
Пользователь Bot
Входные данные
  • init_params: jiraUrl, issueProject, issueType, issueComponent, issueAssignee, issueSummary, issueDescription, fileDirectory, countLimit
  • credential: jira_jsd_credentials (login/password для Jira API)
  • из транзакции: scriptResult (count), dateTime
Основной путь
  1. Бот получает credentials jira_jsd_credentials из Orchestrator;
  2. Бот формирует описание задачи, подставляя %{count}, %{directory}, %{count_limit} из init_params и scriptResult;
  3. Бот формирует заголовок задачи (issueSummary с подставленной датой/временем);
  4. Бот создаёт задачу в Jira (проект, тип, компонент, описание, customfield_18311);
  5. Бот назначает исполнителя issueAssignee на созданную задачу;
  6. Бот сохраняет ticketId в транзакцию.
Альтернативные пути Если полученный issueId пуст или null, Бот выбрасывает IllegalStateException и процесс останавливается.
Выходные данные
  • ticketId (String) — ключ созданной задачи Jira (например SOX-12345)
Дополнительные требования Учётная запись jira_jsd_credentials должна иметь права на создание задач в проекте SOX и назначение исполнителя SC_SG_Mediation_Service.
Возможные исключения ICS-00012-EX-03
