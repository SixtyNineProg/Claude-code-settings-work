Идентификатор ICS-60001-Step-03
Определение Подготовка списков типов документов
Пользователь Bot
Входные данные
  • accountingDocumentPositions
  • InitParameters (documentTypePolicyEditorActionLink, emailRecipients)
  • Ресурсы: document_type_classification (allowed/denied), document_type_comments
Основной путь
  1. Бот загружает классификатор document_type_classification (allowedDocTypes, deniedDocTypes) и справочник document_type_comments;
  2. Бот определяет неклассифицированные коды из accountingDocumentPositions, отсутствующие в allowed и denied;
  3. Бот формирует и сортирует списки allowedDocList, deniedDocList, unclassifiedDocList (код → комментарий);
  4. Бот сохраняет списки в транзакцию;
  5. Бот ставит в очередь Оркестратора "ICS-60001 Document type policy editor" задачу documentTypePolicyEditor с тегом pendingPolicyUpdate и параметрами (initialData, transactionName, processStage=2);
  6. Бот отправляет уведомление task_assigned (Обновление справочника) на emailRecipients.
Альтернативные пути Если asset document_type_comments пуст или невалиден, Бот использует пустой Map комментариев; если document_type_classification пуст, списки allowed/denied считаются пустыми.
Выходные данные
  • allowedDocList, deniedDocList, unclassifiedDocList — списки кодов с комментариями
  • Задача documentTypePolicyEditor в очереди "ICS-60001 Document type policy editor"
Дополнительные требования Системное свойство transaction.path должно быть задано средой Sherpa.
Возможные исключения ICS-60001-EX-04
