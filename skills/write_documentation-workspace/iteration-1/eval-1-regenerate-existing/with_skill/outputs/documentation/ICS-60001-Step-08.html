Идентификатор ICS-60001-Step-08
Определение Рассылка заданий исполнителям
Пользователь Bot
Входные данные
  • sampleDocuments, sampleOwners, ownersEnriched
  • controllerName (из транзакции, при наличии)
  • InitParameters (processName, controlName, controllerEmail, emailRecipients, documentReviewActionLink)
  • sherpa_api_credentials
Основной путь
  1. Бот формирует список email активных владельцев из ownersEnriched (active=true, sapLogin ∈ sampleOwners) и список неактивных логинов;
  2. Бот строит строки таблицы mainTable (number, docNumber, date, amount, currency, account, userName, text) по sampleDocuments;
  3. Бот отправляет письмо multitask_new (emailService.sendByTemplateName) активным владельцам с копией на emailRecipients.to и контекстом (processName, controllerEmail, controllerName, controlName, expireDate, expireTime, inactiveEmailUsers, mainTable);
  4. Бот отправляет контролёру уведомление task_assigned (Проверка ручных проводок) со ссылкой documentReviewActionLink;
  5. Бот для каждого sampleDocument создаёт задачу documentReview в очереди "ICS-60001 Document review" с тегом pendingReview (initialData: sampleDoc, bearerToken из sherpa_api_credentials);
  6. Бот обновляет первую задачу в очереди "ICS-60001 Document type policy editor", проставляя transactionName и processStage=3.
Альтернативные пути Если активных владельцев нет — письмо multitask_new не отправляется; если emailRecipients.to пуст — контролёру письмо не отправляется.
Выходные данные
  • Письмо multitask_new активным владельцам проводок
  • Письмо task_assigned контролёру
  • Задачи documentReview в очереди "ICS-60001 Document review"
  • Обновлённая задача в очереди "ICS-60001 Document type policy editor" (processStage=3)
Дополнительные требования Системное свойство transaction.path должно быть задано средой Sherpa; ресурс sherpa_api_credentials должен содержать токен API.
Возможные исключения ICS-60001-EX-08
