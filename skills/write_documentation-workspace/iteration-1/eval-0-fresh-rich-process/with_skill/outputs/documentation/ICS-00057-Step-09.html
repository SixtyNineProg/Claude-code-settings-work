Идентификатор ICS-00057-Step-09
Определение UploadEvidenceStep — Загрузка результатов на SharePoint и в Storage
Пользователь Bot
Входные данные
  • InitParameters (emailRecipients, storageFolderName, spVactproBase, spVactproProject, spVactproPath, unloadingFileName, screenshotsFileName)
  • ReportingPeriod, sapScreenshotsStorageName, sapUnloadingStorageName — из транзакции
  • checklistAccounts, mtComments — из транзакции
Основной путь
  1. Бот вычисляет унифицированную структуру папок (FolderStructure.from(reportingPeriod)) и временный каталог;
  2. Бот получает sharepoint_credentials и создаёт SharePointService;
  3. Бот скачивает скриншоты и выгрузку обратно из Orchestrator Storage (по sapScreenshotsStorageName / sapUnloadingStorageName) в подкаталоги screenshots/ и input data/ временной папки;
  4. Бот формирует чек-лист ICS-00057_01.xlsx из checklistAccounts (сортировка по номеру счёта) через ExcelChecklistHelper;
  5. Бот формирует ZIP-архив <runDate> archive ICS-00057_01.zip (скриншоты и выгрузка внутри подкаталогов, чек-лист в корне) и вычисляет его MD5;
  6. Бот загружает чек-лист и архив в Orchestrator Storage (плоское имя с суффиксом даты-времени) и в SharePoint по унифицированной структуре папок;
  7. Бот обновляет ассеты состояния в Storage: ics00057_accounts.json и ics00057_comments.json через ProcessStateService;
  8. Бот удаляет временный каталог;
  9. Бот отправляет письмо work_end со ссылкой на папку SharePoint с результатами.
Альтернативные пути —
Выходные данные
  • чек-лист ICS-00057_01.xlsx и ZIP-архив в Orchestrator Storage и SharePoint
  • обновлённые ics00057_accounts.json, ics00057_comments.json в Storage
  • md5Checksum — в ProcessTransaction
  • письмо work_end со ссылкой на результаты
Дополнительные требования Локальные файлы SapStep не переживают MT-шаги (бот-сессия разрывается), поэтому скриншоты и выгрузка скачиваются из Storage заново
Возможные исключения ICS-00057-EX-04, ICS-00057-EX-07
