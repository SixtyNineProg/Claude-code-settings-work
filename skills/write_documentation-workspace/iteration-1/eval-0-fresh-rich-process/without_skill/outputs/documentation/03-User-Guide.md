# Руководство пользователя — ICS-00057 «Обновление справочника»

Документ предназначен для **контролёра** (оператора MT-форм), **администратора Orchestrator** и **владельца процесса**. Описывает повседневную работу с процессом, ручные задачи (MT №1–№3), email-уведомления и типовые действия при инцидентах.

## 1. Роли

| Роль | Что делает в процессе |
|---|---|
| Контролёр | Открывает MT-формы из Action-ссылки в письме или из UI Shadow Core Engine, проверяет счета, заполняет релевантность/комментарии/метки, отправляет результат |
| Администратор Orchestrator | Настраивает ассеты, очередь `ICS-00057 Обновление справочника`, триггеры Task Queue, Action-ссылки в init_params |
| Владелец процесса | Получает email-уведомления, контролирует корректность, эскалирует инциденты |

## 2. Запуск процесса

Процесс запускается **по расписанию** Orchestrator (расписание настраивается администратором). Никаких ручных действий для старта не требуется — после запуска контролёр получает письмо «ботопроцесс запущен» (шаблон `process_started`).

Параметры запуска (через init_params среды):
- `periodStart` / `periodEnd` (`dd.MM.yyyy`) — отчётный период. `"-"` = предыдущий квартал от даты запуска.
- `mockSap` (`"true"` / `"false"`) — использовать ли мок-SAP вместо реальной выгрузки.

## 3. Email-уведомления

Все письма приходят на `SOX_Workfusion_App_RPA_ICS-00057@a1.by` (копия: `SC_SG_WorkFusion@A1.by`).

| Письмо | Когда приходит | Что делать |
|---|---|---|
| Ботопроцесс запущен | Старт процесса | Ничего, информационно |
| Новая задача — `<MT>` | Бот создал MT №1/№2/№3 и ждёт ручной проверки | Открыть ссылку «открыть» в письме — попадёте в форму MT |
| Новых задач нет — `<MT>` | Бот не нашёл новых / изменённых счетов (MT №1 или №2) | Ничего, информационно — следующая стадия стартует автоматически |
| Задача обработана — `<MT>` | Бот разобрал ваш результат из MT | Ничего, информационно |
| Работа завершена | Процесс закончил выгрузку доказательств | Открыть ссылку на SharePoint — там чек-лист и архив |
| Ошибка во время исполнения ботопроцесса | Бот остановился с ошибкой | См. раздел 7 «Действия при ошибках» |

## 4. Ручные задачи (Manual Task)

### 4.1. MT №1 «Проверка новых счетов»
- **Когда**: бот нашёл в SAP счета, отсутствующие в справочнике.
- **Форма**: `actions/process_new.js` — две таблицы: «без меток» (редактируемые) и «с метками» (неизменяемые — только просмотр).
- **Что делать**:
  1. Откройте Action-ссылку из письма «Новая задача — Проверка новых счетов».
  2. В таблице «без меток» для каждого счета выберите релевантность («Включить» / «Исключить») и заполните комментарий (с автодополнением из истории комментариев).
  3. Таблица «с метками» — информационная, недоступна для правки.
  4. Нажмите «Отправить». До тех пор, пока есть незаполненные релевантности/комментарии, кнопка не отправит данные (незаполненные поля помечаются красной рамкой).
- **Если новых счетов нет**: бот создаст auto-trigger задачу — форма не появится, следующая стадия стартует автоматически, придёт письмо «Новых задач нет».

### 4.2. MT №2 «Проверка изменения меток счетов»
- **Когда**: у существующих счетов в SAP изменились метки «блокировка проводки» (`hasPostingBlockMark`) или «пометка удаления» (`hasDeletionMark`).
- **Форма**: `actions/process_changed.js` — две таблицы: «без меток» (редактируемые) и «с метками» (неизменяемые). Каждая строка показывает предыдущее состояние (`accountPrev`) и новые значения меток.
- **Что делать**: аналогично MT №1 — заполнить релевантность и комментарий в редактируемой таблице, нажать «Отправить».
- **Auto-trigger**: если изменений меток нет, придёт письмо «Новых задач нет — Проверка изменения меток», Stage3 стартует автоматически.

### 4.3. MT №3 «Внесение изменений по счетам»
- **Когда**: всегда после MT №2 (задача безусловна).
- **Форма**: `actions/process_all.js` — контролёр сам добавляет счета для корректировки через autocomplete по номеру счета (использует полный справочник `allAccounts`).
- **Что делать**:
  1. Откройте Action-ссылку из письма «Новая задача — Внесение изменений по счетам».
  2. Добавьте нужные счета (по номеру — автодополнение подскажет существующие).
  3. Заполните релевантность, комментарий, метки.
  4. Нажмите «Отправить».
- **Если правок нет**: просто отправьте пустую форму — `processedAccounts` будет пустым списком, бот корректно это обработает.

## 5. Что формирует бот по итогу

В SharePoint (папка периода `Бот/<год>/<период>/<01_Обновление справочника>/<runDate>/`):
- `input data/ZACCOUNTS.xlsx` — выгрузка SAP
- `screenshots/screenshots.xlsx` — скриншоты экранов SAP (параметры, первая страница, последняя страница)
- `ICS-00057_01.xlsx` — чек-лист со всем справочником (отсортирован по номеру счета)
- `<runDate> archive ICS-00057_01.zip` — технический архив (вложены `screenshots/`, `input data/`, чек-лист в корне)

В Orchestrator Storage (плоское имя с суффиксом даты-времени):
- Те же 4 файла с суффиксом `_yyyyMMdd_HHmmss` перед расширением.

В ассетах Orchestrator:
- `ics00057_accounts` — обновлённый справочник
- `ics00057_comments` — накопленный справочник комментариев

## 6. Письмо «Работа завершена»

Содержит ссылку на папку SharePoint с результатами периода. Откройте её, чтобы:
- Просмотреть чек-лист `ICS-00057_01.xlsx` (актуальное состояние справочника).
- Скачать технический архив `<runDate> archive ICS-00057_01.zip` для аудита.

## 7. Действия при ошибках

Когда бот падает, приходит письмо «ошибка во время исполнения ботопроцесса» (шаблон `process_error`). Если в init_params задан `errorHandling.errorOccursUrl`, письмо содержит ссылку «Порядок действий при возникновении ошибок».

Типовые шаги:
1. Открыть Orchestrator, найти транзакцию процесса ICS-00057 — посмотреть логи SLF4J.
2. Проверить доступность внешних систем:
   - SAP GUI — запущен ли `saplogon.exe`, доступны ли учётные данные в ассете `sap_credentials`, корректен ли `sap_settings`.
   - SharePoint — доступен ли `vactpro.main.velcom.by`, действуют ли `sharepoint_credentials`.
   - Orchestrator Storage — доступна ли папка `ICS-00057`, не превышена ли квота.
3. Если ошибка в разборе MT-результата (`Failed to parse MT task`) — проверить, что контролёр отправил форму через `ShadowCore.submit` (а не закрыл вкладку).
4. Если auto-trigger пере-сработал (задача осталась в `IN_PROGRESS` с тегом `reviewed`/`reviewedChanged`/`reviewedAll`) — вручную перевести задачу в `SUCCESS` и заменить теги на `processed*`.
5. Перезапустить транзакцию через Orchestrator после устранения причины.

## 8. Что НЕ нужно делать

- Не закрывать вкладку MT-формы без нажатия «Отправить» — результат не будет зафиксирован, задача останется в `pending`/`pendingChanged`/`pendingAll`.
- Не редактировать вручную ассет `ics00057_accounts` во время работы бота — состояние будет перезаписано `UploadEvidenceStep`.
- Не удалять файлы из Orchestrator Storage с суффиксом даты — это исторические доказательства.
- Не менять `processStage` в параметрах MT-задачи вручную — это нарушит маршрутизацию по стадиям.

## 9. Тестовое окружение

В test-среде `mockSap = "true"` — бот берёт выгрузку из ресурсов `sap_mock/excel/`, SAP GUI не нужен. Action-ссылки ведут на `sherpa-test.a1.by`. Используйте test-окружение для обучения контролёров и проверки правок MT-форм.
