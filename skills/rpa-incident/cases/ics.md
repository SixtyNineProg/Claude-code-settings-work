# ICS — Кейсы инцидентов

Решённые инциденты для семейства процессов ICS (Sherpa Manual Tasks: ics00057-accounts, ics60001 и др.).

Отличие от WorkFusion-семейств (OPI/ACI/STB/UCG): ICS-процессы работают на платформе Sherpa, используют
HTML-формы ручных задач (Manual Tasks) на базе Shadow Core Engine (`rpa-core/.../manualtask/core.js`).
Сбои чаще всего в frontend-логике (core.js / mt-скрипты) или конфигурации Действия в Дизайнере, а не в
транзакциях/Excel. Repair-механика WorkFusion неприменима — перезапуск идёт через создание/завершение
задач в очереди Sherpa.

## Кейс 1: System save button not found — устаревший селектор Angular Material (ICS-00057 MT №2)

**Дата:** 2026-07-31
**Jira:** — (ветка feat/ics00057-accounts-RPA-16567)
**Процесс:** ics00057-accounts, MT №2 «Проверка изменения меток счетов»
**Шаг:** submit формы пользователем (кнопка «Завершить» в виджете)
**Сигнатура ошибки:** `[ShadowCore] ERROR: System save button not found! Data injected into input, but form not submitted.`
**Категория причины:** Баг кода — устаревший CSS-селектор после миграции платформы на Angular Material MDC
**Причина:** Платформа Sherpa мигрировала на Angular Material v15+ (MDC). Системная кнопка завершения (настраивается в Дизайнере во вкладке «Кнопки действий», логика «Сохранить изменения в текущей задаче» + финальный тег) теперь имеет класс `mat-mdc-raised-button`, а не legacy `mat-raised-button`. `core.js:performInjection()` искал её селектором `.btn-container .mat-raised-button` → `querySelector` возвращал null → кнопка не нажималась, форма не сабмитилась в платформу, хотя данные уже впрыснуты в скрытый Angular-инпут `initialData`.
**Данные-триггер:** Любые корректные данные формы — сбой не зависит от данных, чисто frontend.
**Подтверждённый DOM кнопки:** `<div class="btn-container"><button mat-raised-button="" class="... mat-mdc-raised-button mat-primary ...">…<span class="mdc-button__label"> New </span>…</button></div>`. Обёртка `.btn-container` присутствует, текст кнопки задаётся в Дизайнере (здесь «New»).
**Важный нюанс диагностики:** Пользователь сначала по ошибке указал селектор виджет-кнопки `<button id="submitBtn">Завершить</button>` — это собственная кнопка формы в Shadow DOM, её клик уже обрабатывает mt-скрипт (`ShadowCore.submit()`). Кликать её из core.js НЕЛЬЗЯ — бесконечный цикл (submit → inject → снова submit). core.js должен кликать именно ПЛАТФОРМЕННУЮ системную кнопку из «Кнопок действий», которая лежит в light-DOM вне Shadow-root.
**Исправление (код):** В `rpa-core/src/test/resources/manualtask/core.js`, `performInjection()`: заменить одиночный `document.querySelector(".btn-container .mat-raised-button")` на список кандидатных селекторов (legacy + MDC) + retry-цикл (polling 50 мс, до ~2 с), с логированием совпавшего селектора. Legacy-селектор оставлен для обратной совместимости с остальными MT-процессами.
**Исправление (данные):** Не требуется.
**Repair:** Не применимо (Sherpa, не WorkFusion). После деплоя исправленного core.js в файловое хранилище платформы (обновить ID файла в сниппете) — перезапустить задачу.
**Общая папка:** Не применимо (нет общей SMB-папки).
**Затронутые процессы:** ВСЕ MT-процессы на Sherpa, использующие `core.js` (ics00057-accounts MT №1/№2/№3, ics60001 document-type-policy-editor и любые другие). До деплоя фикса ни один из них не мог сабмитить форму на платформе с MDC-кнопкой — симптомы одинаковые.
