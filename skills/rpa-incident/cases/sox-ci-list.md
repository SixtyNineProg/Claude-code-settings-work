# Кейсы: SOX CI List

## Кейс 1: Last SP file not found — несовпадение regex имени файла

**Сигнатура ошибки:** `AppProcessException: Last SP file not found.` (в `JsdTaskHandler.java:178`)

**Дата:** 2026-06-18

**Процесс:** `sox_ci_list_ics_60112_changes_writer`

**Корневая причина:** Баг кода. Regex `SOX_CI_LIST_FILE_NAME_PATTERN` в `JsdTaskHandler.java:65-66` ожидает имена файлов вида `sox_ci_list_YYYY-MM-DD_HH-MM.xlsx`, но процесс `report_creator` создаёт файлы с именами `sox_ci_list_wf_upload_YYYY-MM-DD_HH-MM.xlsx`. Промежуточная часть `wf_upload_` не учтена в regex, что приводит к пустому результату фильтрации и исключению `orElseThrow`.

**Решение:** Изменить regex на `sox_ci_list_.*_\\d{4}-\\d{2}-\\d{2}_\\d{2}-\\d{2}\\.xlsx` для гибкого совпадения.

**Затронутые процессы:**
- `sox_ci_list_ics_60112_changes_writer`

**Repair note:** Обычный ремонт упавшего шага НЕ сработает — ошибка воспроизводится из-за бага кода. Нужен деплой с исправлением regex.

## Кейс 2: ICS-00040 — выявлены расхождения при совпадающих данных в источниках

**Сигнатура ошибки:** статус из бота `выявлены расхождения.`, хотя визуальная проверка исходных файлов `cc_062026.xlsx` (CC_BSCS) и `Credit_class_definition.xlsx` (CC_Master_Data) показывает совпадение. В Groovy/логах нет стека — процесс завершается `Step_3` со штатным статусом.

**Дата:** 2026-06-24 (тикет RPA-17879, репортер Tatiana_Bu, файлы во вложении)

**Процесс:** `ICS-00040 Check for credit limit parameters` (BCB), Step_2 (`ICS-00040-Excel.xml`).

**Корневая причина (гипотезы, не подтверждена):**

1. **Power Query не обновился до актуального состояния.** Макрос `FINby_macro.Update_queries` (`resources/Excel/FINby_macro.bas`) использует `On Error Resume Next`, который подавляет ошибки. Если `ListObject.QueryTable` для одной из таблиц не найден (имя в `name_ref_data`/`name_cc_def` не совпадает с реальным именем ListObject/QueryTable в книге), ошибка проглатывается, MsgBox показывает «Обновление завершено успешно» (т.к. `errMsg = ""` → первая ветка), но Refresh фактически не выполнен → сравнение идёт по устаревшим данным.

2. **Excel-кэш Power Query.** Даже если Refresh прошёл, при `BackgroundQuery:=False` источник должен перечитаться. Если источник запроса недоступен из-под бота (например, сетевой путь), Refresh может пройти формально, но без реального обновления строк.

3. **Несоответствие имён ListObjects.** Бот в Step_2 подставляет в `name_ref_data`/`name_cc_def` **имена файлов** (`cc_062026`, `Credit_class_definition`) — но эти ячейки должны содержать имена таблиц/запросов, зашитых в инструмент `ICS 00040 - Проверка лимитов кредитных классов vL.xlsm`. Если имена в инструменте отличаются — Refresh не сработает.

4. **Реальное расхождение не видно глазом.** Например, `100` vs `100.00`, разные регистры или невидимые пробелы в одной из колонок. Без открытия файла результата не обнаружить.

**Решение (по приоритету):**

1. Открыть файл результата в SharePoint: `\\vactpro.main.velcom.by@SSL\...\Бот\Результат\31.05.2026 v2026-06-23 0008\Инструмент\ICS 00040 - Проверка лимитов кредитных классов vL.xlsm`. Найти лист с итогами сверки — там должны быть видны конкретные строки расхождений (какие кредитные классы и какие колонки). Это сразу отделяет гипотезы 1-3 от гипотезы 4.

2. Открыть инструмент и вручную запустить Refresh All в Power Query. Если после ручного Refresh расхождения исчезли → виноват макрос (нужно убрать `On Error Resume Next` и явно логировать `errMsg`).

3. Проверить Power Query в инструменте — какие источники у запросов, доступны ли они из среды бота, не изменились ли пути/учётки.

4. Сравнить `cc_062026.xlsx` и `Credit_class_definition.xlsx` по агрегатам (суммы, COUNT DISTINCT по `cc` и `account_class_id`) — расхождение может быть в скрытых колонках или в колонке с переименованием.

5. Долгосрочно: убрать `On Error Resume Next` из `FINby_macro.bas`, выводить `errMsg` явно (MsgBox + запись в файл логов).

**Затронутые процессы:** только `ICS-00040` (уникальный инструмент и макрос).

**Repair note:** Repair не применим — процесс не «упал», завершился штатно со статусом «выявлены расхождения». Нужен анализ файла результата в SharePoint, а не перезапуск.
