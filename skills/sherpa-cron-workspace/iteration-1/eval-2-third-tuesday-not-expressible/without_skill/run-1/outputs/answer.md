# Запуск отчёта каждый третий вторник месяца в 9:00

## Главное
**Стандартным cron-выражением (5 полей) это напрямую задать нельзя.** Придётся использовать обходной путь.

## Почему нельзя
Формат классического cron (5 полей):

```
минута  час  день_месяца  месяц  день_недели
```

Проблема в том, что поля «день месяца» и «день недели» объединяются через логическое **ИЛИ**, а не **И**. Правило срабатывает, если совпало *любое* из двух ограничений, а не оба одновременно.

Наивная запись:

```
0 9 15-21 * 2
```

означает «в 9:00 в любой день с 15 по 21 число **ИЛИ** в любой вторник». На практике это даст запуск почти каждую неделю — совсем не то, что нужно.

«Третий вторник» — понятие порядковое (n-е вхождение дня недели в месяце). В 5-полевом cron такого понятия нет: нельзя написать «вторник, но только третий по счёту».

Вывод: **нужен либо cron с расширенным синтаксисом, либо проверка даты внутри самого процесса.**

## Как решить

### Вариант 1 (рекомендуемый). Cron + проверка даты в процессе
1. Расписание: `0 9 * * 2` — «каждый вторник в 9:00».
2. Первым шагом процесса проверяем число месяца: третий вторник всегда попадает в диапазон **15–21**.
   - если число месяца от 15 до 21 → это третий вторник, выполняем отчёт;
   - иначе → завершаем процесс, ничего не делая.

   Логика проверки: `if (день_месяца >= 15 && день_месяца <= 21) { выполнять отчёт } else { выход }`

Почему 15–21: первый вторник месяца выпадает на 1–7, второй — на 8–14, третий — на 15–21, четвёртый — на 22–28. Этот диапазон однозначно отделяет третий вторник от остальных.

Плюсы: работает на любом планировщике со стандартным cron. Минус: раз в неделю процесс стартует «вхолостую» (можно отключить уведомление об успехе для холостых запусков).

### Вариант 2. Quartz-совместимый планировщик (если поддерживается)
Если планировщик Шерпы принимает Quartz-синтаксис (6–7 полей, с `?` и `#`), задача решается штатно:

```
0 0 9 ? * 3#3
```

где `3#3` = «третий вторник» (в Quartz: 1=Вс, 2=Пн, 3=Вт …), а `?` = «день месяца не важен». Обязательно проверьте, какой именно диалект cron принимает ваш планировщик — от этого зависит, подходит ли этот вариант.

### Вариант 3. Внешний триггер по списку дат
Если планировщик совсем не гибкий: держать перечень дат третьих вторников и запускать по нему (планировщик ОС, внешний оркестратор, ручной запуск по календарю).

## Рекомендация
Проверьте документацию планировщика Шерпы на поддерживаемый диалект cron:
- **Quartz поддерживается** → используйте `0 0 9 ? * 3#3`.
- **Только 5-полевой Unix-cron** → берите Вариант 1 (обёртка с проверкой числа месяца 15–21).

## Принятые допущения
- Планировщик Шерпа по умолчанию использует классический 5-полевой cron; если у вас включён Quartz-формат — примените Вариант 2.
- «9:00» — время сервера/планировщика (не UTC и не время клиента); уточните нужный часовой пояс.
- «Третий вторник» = третье по счёту вхождение вторника в календарном месяце.
- Отчёт запускается один раз в месяц (а не «каждый третий вторник среди вторников квартала» и т.п.).
