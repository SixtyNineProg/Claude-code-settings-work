# Да, всё в порядке — расхождение мнимое, это часовой пояс

## Короткий ответ

`cron_tab = 0 9 * * *` и `last_run = 2026-10-01T06:00:00Z` **согласованы между собой**. Числа выглядят
разными только потому, что они в разных часовых поясах:

- `cron_tab` считается в **местном времени Sherpa — Минск, UTC+3**;
- API `/schedules` отдаёт `last_run` (а также `created` и `enabled_at`) в **UTC**.

06:00 UTC + 3 часа = **09:00 по Минску**. Это ровно тот час, который задаёт выражение. Менять
расписание не нужно.

## Расшифровка выражения

```
0 9 * * *
│ │ │ │ └── день недели: *  — любой день недели
│ │ │ └──── месяц:      *  — любой месяц
│ │ └────── день месяца: * — любое число
│ └──────── час:        9  — 9 часов (09:00 по Минску)
└────────── минута:     0  — на нулевой минуте
```

Человеческим языком: **каждый день в 09:00 по Минску (UTC+3)**, то есть каждый день в
**06:00 UTC**.

## Сверка двух чисел

| Источник | Значение | Пояс |
|---|---|---|
| `cron_tab` | 09:00 | локальное время Sherpa (Минск, UTC+3) |
| `last_run` | 06:00:00Z | то же самое мгновение, но в UTC |

Если привести к одной шкале: `06:00Z + 3 ч = 09:00` — совпадает с `час=9` из выражения. Разница ровно
3 часа набегает на смещении пояса, а не на ошибке в расписании.

## Сделанные допущения

1. Задача уже включена (`enabled`) и запускалась штатно по расписанию — то есть `last_run` отражает
   именно плановый запуск, а не ручной пуск или запуск по событию.
2. Часовой пояс площадки Sherpa — Минск (UTC+3), фиксированное смещение без перехода на летнее
   время. Скрипт работает без базы tzdata и применяет ровно +3 часа круглый год, что для Минска
   корректно (Беларусь с 2011 года не переходит на летнее время).
3. `last_run` в выгрузке — действительно UTC (формат с суффиксом `Z`), а не локальное время с
   ошибочной меткой.

## Предупреждения

Нет. Выражение `0 9 * * *` использует только проверенный на проде синтаксис (`*` и числовые
значения), синтаксис валиден, непроверенных конструкций (имена дней/месяцев, `?`, `7` как
воскресенье) в нём нет.

## Что делать, если расхождение всё-таки есть

Если у другой задачи `last_run` **не** согласуется с `cron_tab` даже после прибавления 3 часов —
проверять надо не выражение, а часовой пояс площадки: возможно, задача отработала вручную
(`processing_type = 1`, пустой `cron_tab`) или на стенде настроен другой пояс.
