# Очистка кешей

## Зачем

Ручная чистка по инструкции (`%temp%`, `temp`, `prefetch`, `cleanmgr`, `wsreset.exe`) бьёт мимо
цели: системные temp-папки занимают ~56 МБ, а кеши dev-тулчейна — ~3.4 ГБ (npm 1.16 ГБ,
`.m2` 1.12 ГБ, Gradle 1.05 ГБ, pip 254 МБ). Место на C: обычно и есть причина запроса.

Внутри «кеша npm» две разные вещи: `_cacache` (чистится `npm cache clean --force`) и `_npx`
(не чистится ничем — у npm нет для него команды). Основной объём обычно в `_npx`.

Скилл показывает реальные размеры, помечает риск каждой категории, предупреждает о занятых
кешах и удаляет только подтверждённое.

## Когда использовать

- «почисти кеши», «освободи место на C:», «мало места на диске»
- подозрение на протухший кеш (пакет не переустанавливается, билд берёт старую версию)

**Не использовать** перед работой без сети: `.m2` и Gradle после чистки не соберутся.
Предупредить об этом до очистки.

## Быстрый справочник

| Категория | Риск | Восстанавливается |
|---|---|---|
| `temp`, `windows-temp`, `prefetch`, `thumbnails`, `inetcache` | низкий | да, само |
| `store-cache`, `disk-cleanup` | низкий | интерактивные GUI-инструменты |
| `npm`, `pip` | низкий | да, повторной загрузкой |
| `npm-npx` | низкий | да, при следующем запуске `npx` |
| `gradle` | **высокий** | да, полной перекачкой зависимостей |
| `maven` | **высокий** | **не гарантировано** — внутренние артефакты A1 (`a1lib`, `by.a1`) могут не восстановиться |
| `claude-shell-snapshots`, `claude-paste-cache` | низкий | да |
| `claude-file-history` | **средний** | **нет** — теряется история правок |

Полный список с путями — таблица `$cacheCategories` в `scripts/clear-caches.ps1`.

## Workflow

1. **Скан без удаления** — `-Categories <имена>` без `-Force`: печатает размеры, ничего не удаляет.
   ```powershell
   .\scripts\clear-caches.ps1 -Categories temp,npm,pip
   ```
   В неинтерактивной сессии подтверждение недоступно → скрипт вернёт «отказ» по всем
   категориям и явно скажет об этом. Это безопасный дефолт, а не сбой.
2. **Показать человеку таблицу** — размеры, риск, «нужен админ», предупреждение о занятых кешах.
3. **Получить явное согласие** на конкретные категории.
4. **Удалить** `-Force` — только после согласия:
   ```powershell
   .\scripts\clear-caches.ps1 -Categories temp,npm,pip -Force
   ```

Без `-Categories` скрипт интерактивен: вопрос по каждой категории, дефолт «нет».

## Common Mistakes

- **Ждать, что `npm cache clean --force` очистит весь `npm-cache`.** Он чистит только `_cacache`;
  основной объём (обычно ~1 ГБ) лежит в `_npx` — это отдельная категория `npm-npx`.
- **Считать `.m2` обычным кешем.** Там внутренние артефакты A1 — при недоступности
  корпоративного Nexus они не восстановятся. Единственная категория с необратимым риском.
- **Чистить `.m2`/Gradle при запущенной IDE.** IDEA и демоны держат локи: занятые файлы молча
  пропускаются, чистка выглядит успешной. Для полного эффекта сначала закрыть IDE.
- **Чистить `%TEMP%` при работающей сессии Claude Code.** В `%TEMP%\claude\` лежат файлы задач
  текущей сессии; занятые пропустятся, но нуля освобождённого не будет.
- **Удалять `~\.claude\projects`.** Там история сессий — категории для неё нет намеренно.

Что скрипт делает сам: удаляет только содержимое (не саму папку), останавливает демон Gradle
перед чисткой `caches`, пропускает админ-категории без прав, предупреждает о занятых кешах и
о том, что `cleanmgr`/`wsreset` интерактивны.

## Red Flags — остановиться

- Запуск с `-Force` без явного согласия человека **в текущем разговоре**
- «Удалю всё, чтобы наверняка» / «почисти кеши, значит и `.m2` можно»
- Показывать отчёт после удаления вместо скана до него
