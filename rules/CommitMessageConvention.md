# Правила написания коммитов (корпоративный стандарт A1)

## Формат сообщения коммита

```
<process_name> <jira_issue_number> <summary>

[пояснения с использованием сокращений]
```

**Пример:**
```
#ics60181 RPA-16567 Получение данных из Bitrix 24

[+] заготовка шага
[+] тестовый сервис, без реализации API
```

## Структура сообщения

1. **process_name** — краткое название процесса или номер задачи из Jira
2. **jira_issue_number** — номер задачи Jira (опционально). Берётся из названия текущей ветки git
   (например, из `feat/ics00057-accounts-RPA-16567` → `RPA-16567`). Если в названии ветки номера задачи нет
   — поле опускается.
3. **summary** — краткое описание изменений в повелительном наклонении
4. **пояснения** — детали изменений через пустую строку (опционально)

## Сокращения для пояснений

| Сокращение | Значение |
|------------|----------|
| `[+]` | создание |
| `[-]` | удаление |
| `[*]` | изменения |
| `[~]` | очень мелкие правки |
| `[!]` | важное исправление |
| `[r]` | рефакторинг |
| `[t]` | изменения в тексте или документации |

## Общие правила

1. Первая строка — краткое название с процессом/задачей
2. Вторая строка — всегда пустая (разделитель)
3. Пояснения — список изменений с сокращениями
4. Переносы строк — для удобства чтения в gitk
